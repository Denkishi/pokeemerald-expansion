# Plan: Implement Functional NPC Team Rental System

## Goal
Implement a fully functional NPC team rental system that allows players to select from pre-implemented teams without causing game crashes.

## Current context / assumptions
- The project is a GBA Pokemon Emerald disassembly in a Git repository.
- The game crashes when navigating back from the team preview screen after selecting a team from the rental system.
- There's existing documentation in the docs directory and an emulation environment in mgba-mcp.
- The current NPC (Bill) needs to be replaced with a fully functional team rental system.
- Game runs in WSL environment with make commands.

## Architecture / proposed approach
1. Analyze current NPC implementation and crash cause
2. Create new team rental NPC with full implementation to replace Bill
3. Implement team selection, preview, and return flow
4. Ensure code compatibility with GBA constraints
5. Test in emulator environment

## Step-by-step tasks
### Task 1: Analyze the crash point

## Analysis Findings

The crash occurs in the following key areas:
1. Rental teams menu system in src/rental_teams.c 
2. Field callback management during navigation back
3. Preview screen handling in team selection flows
4. Callbacks to return from preview to field state

## Key Observations:
- The issue occurs when navigating back from team preview screen
- Memory management is crucial - both data pointer and sprite tracking
- Callbacks to maintain field state are critical
- The existing implementation is non-functional due to:
  - Improper field callbacks
  - Memory management issues
  - Event flow problems
